# Model Card

## Общая информация

**Название модели:**
`blanchefort/rubert-base-cased-sentiment-rurewiews` (RuBERT for Sentiment Analysis of Product Reviews)

**Источник:**
[Hugging Face Hub](https://huggingface.co/blanchefort/rubert-base-cased-sentiment-rurewiews)

**Автор / организация:**
`blanchefort` (пользователь Hugging Face). Базовая модель —
[DeepPavlov/rubert-base-cased-conversational](https://huggingface.co/DeepPavlov/rubert-base-cased-conversational)
от DeepPavlov.

**Задача модели:**
Классификация текста (`text-classification`) — определение тональности отзыва о товаре.
Три класса: `0: NEUTRAL`, `1: POSITIVE`, `2: NEGATIVE`.

**Язык:**
Русский (`ru`).

**Архитектура:**
`BertForSequenceClassification`, дообученный Conversational RuBERT
(12 слоёв, 768 hidden, 12 heads, около 180M параметров — по данным карточки базовой модели).

**Лицензия:**
Не указано авторами модели.

## Использование в проекте

Модель — компонент «ML-модель» сервиса «Анализатор отзывов»
(см. [Диаграммы](../project/diagrams.md)) и реализует шаг 4 сценария
[UC-01](../project/requirements.md#uc-01).

1. Пользователь отправляет отзыв через `POST /analysis` (см. [API](../api/index.md)).
2. Система проверяет длину текста (1–5000 символов) и передаёт очищенный текст модели.
3. Модель возвращает вероятности трёх классов. Класс с наибольшей вероятностью становится
   полем `sentiment`, а его вероятность — полем `confidence`.
4. Если `confidence < 0.6`, система ставит `needsReview = true` и помечает результат
   как «требует проверки» (US-02).
5. Результат сохраняется в базу данных вместе с версией модели и попадает в статистику
   по тональности для аналитика (US-03).

Метки модели сопоставляются со значениями API так:

| Метка модели | Значение в API |
|---|---|
| `POSITIVE` | `positive` |
| `NEUTRAL` | `neutral` |
| `NEGATIVE` | `negative` |

## Входные данные

Текст отзыва на русском языке (строка). В примере авторов текст токенизируется
`BertTokenizerFast` с `max_length=512` и `truncation=True`: всё, что длиннее 512 токенов,
отбрасывается.

## Выходные данные

Логиты для трёх классов. После `softmax` получаются вероятности классов
`NEUTRAL`, `POSITIVE`, `NEGATIVE`. В примере авторов возвращается индекс класса
с наибольшей вероятностью (`argmax`).

## Ограничения

**Указано авторами модели и датасета:**

- Модель работает с русским языком: в метаданных указан только `ru`.
- Модель дообучена на одном датасете — RuReviews, где собраны отзывы только из категории
  «Женская одежда и аксессуары» одного крупного интернет-магазина
  (см. [Data Sheet](dataset.md)).
- Входной текст ограничен 512 токенами, длинный текст обрезается
  (параметры из примера кода авторов).
- Разметка обучающих данных автоматическая (по оценке в звёздах), а не ручная.
  Авторы датасета отмечают, что одинаковые тексты встречаются с разными оценками.

**Потенциальное ограничение для нашего проекта:**

- Качество может быть ниже на отзывах о других категориях товаров и услуг (электроника,
  рестораны, сервисы): авторы датасета пишут, что одни и те же слова в разных категориях
  могут иметь разную тональность.
- Качество может снижаться на очень коротких отзывах («Норм», «Пришло»), на сарказме
  и на отзывах со смешанной оценкой («товар хороший, доставка ужасная»).
- Класс `neutral` в обучающих данных соответствует оценке 3 из 5. Это не то же самое,
  что «отзыв без эмоций», поэтому нейтральные отзывы в нашем сервисе могут
  классифицироваться хуже.
- Нет данных о работе модели с текстами на английском языке, транслитом и с текстами,
  где смешаны языки.

## Не рекомендуется использовать

- Для автоматического удаления, скрытия или модерации отзывов без проверки человеком.
- Для оценки сотрудников, продавцов или клиентов (премии, санкции, блокировки).
- Для анализа медицинских, юридических и финансовых текстов и для принятия решений в этих областях.
- Для текстов не на русском языке и для задач, отличных от тональности (определение
  эмоций, токсичности, тематики).
